# Анализ генетического профиля

Сервис переносит самостоятельный VCF-конвейер в API. Исходный
`scripts/genes_analysis/analysis.py` остаётся отдельным CLI и не импортируется сервисом.

## API

Префикс: `/api/patients/{patient_id}/genes`. Пациент должен существовать.

| Запрос | Ответ |
| --- | --- |
| `GET /profile` | `{"profile": null}` либо `{"profile": {...}}` с исходным именем и метаданными |
| `POST /profile` | Multipart-поле `file`; после проверки возвращает `200 {"profile": {...}}` |
| `GET /analysis` | Первый запрос рассчитывает и сохраняет JSON; повторный возвращает сохранённый снимок |

Поддерживается несжатый VCF v4 с одним образцом и пригодными диплоидными вызовами.
Лимит по умолчанию — 100 МиБ; переменная `GENE_PROFILE_MAX_BYTES` задаёт лимит в байтах.
Проверка размера выполняется при переносе загруженного файла в постоянное хранилище;
для ограничения всего входящего HTTP-тела настройте также лимит reverse proxy.
Известная сборка, отличная от GRCh37/hg19, отклоняется. Неуказанная/нераспознанная
сборка принимается с `build_source=assumed` и предупреждением в `quality.issues`.

Ошибки: `404` — нет пациента или профиля для анализа; `413` — превышение лимита;
`422` — некорректный VCF; `409` — другая операция или повреждённый сохранённый отчёт;
`500` — ошибка файлового хранилища либо непредвиденная ошибка реализации.

## Жизненный цикл

Изменяемые данные находятся в `server/var/gene_analysis/`, независимо от CWD:

```text
patients/<patient_id>/current.json
patients/<patient_id>/<profile_uuid>/profile.vcf
patients/<patient_id>/<profile_uuid>/metadata.json
patients/<patient_id>/<profile_uuid>/analysis.json
cache/pgs/                         # веса моделей и EUR NPZ
cache/myvariant/                   # завершённые пакеты аннотаций
locks/<patient_id>.lock
```

`current.json` атомарно публикует метаданные текущего поколения. При загрузке
сначала записывается и проверяется новое поколение, затем переключается указатель,
после чего удаляются прежние поколения, включая их отчёты. Неудачная проверка
не меняет текущий профиль. Незавершённые поколения после сбоя игнорируются и
очищаются при следующей успешной загрузке.

Межпроцессная блокировка удерживается во время загрузки, анализа и удаления
пациента. Конкурирующая операция получает `409`. Чтение имени не ждёт анализа.
При удалении пациента удаляются его файлы; кэши общих источников сохраняются.
Файловая система и БД не образуют общую транзакцию: при ошибке удаления БД после
очистки файлов пациент может остаться без профиля, операцию удаления можно повторить.

Отчёт сохраняется атомарно, в том числе при недоступности MyVariant или отдельных
PGS. Частичный отчёт автоматически не обновляется. Для нового анализа загрузите
VCF повторно, даже если содержимое не изменилось. Обновление алгоритма, правил или
источников также не изменяет существующий отчёт. Несовместимый/повреждённый JSON
возвращает `409`, без неявного пересчёта.

Первый анализ полного VCF может занять значительное время. Синхронная обработка
выполняется в рабочем потоке, не в event loop; очередь фоновых заданий не используется.
HTTP-клиент и reverse proxy должны допускать долгий запрос. Лимиты повторов и
тайм-ауты отдельных внешних запросов не являются общим лимитом времени анализа.

## Контракт отчёта и отображение

Схемы находятся в `src/schemas/gene_analysis/`, синтетические примеры — в
`src/schemas/gene_analysis/examples/`. Оба примера также доступны в Swagger.

| Раздел | Отображение |
| --- | --- |
| `profile`, `generated_at`, `schema_version`, `analysis_version` | Заголовок, файл, дата снимка, версии |
| `summary.findings` | Основные находки, вопросы врачу, источники и ссылки на подробные строки |
| `summary.not_detected`, `summary.not_evaluated` | Проверенное отсутствие конкретного аллеля и отдельно невозможность оценки |
| `summary.polygenic_overview` | Одна выбранная модель на признак; подробности по `pgs_id` |
| `clinvar.items` | Таблица классификаций вариантов/состояний, accession, review status и дата оценки |
| `genotype_rules.items` | Все семь правил, наблюдаемые генотипы, диплотипы, результат или причина пропуска |
| `polygenic_scores.items` | Все 14 моделей: покрытие, техническая сумма, EUR-сравнение, устойчивость и исследовательский HR |
| `quality`, `limitations`, `provenance` | Ограничения входа, интерпретации и сведения об источниках |

У разделов есть `status`, `issues`, `items`. Пустой `clinvar.items` при `complete`
означает отсутствие подходящих находок в выполненном анализе; при `unavailable`
означает, что ClinVar не оценён. Верхний `complete` характеризует полноту результатов,
но не медицинскую валидность. `partial` может означать также отсутствие нужных
локусов или референса, а не только сетевую ошибку.

`evidence_refs` содержит `section` и `item_id`; эти ссылки проверяются схемой.
Сортировать/фильтровать следует по кодам, а выводить русские подписи. Числа
не форматируются строками; отсутствующие значения — `null`, интервалы —
`{lower, upper}`. `NaN`/`Infinity` не допускаются. Проценты покрытия имеют суффикс
`_percent`; перцентиль — шкала 0–100. Временные метки содержат часовой пояс.

**Не объединяйте в интерфейсе три разные величины:** `raw_score` — техническая
сумма, `reference_comparison.percentile` — положение балла среди EUR-образцов,
`research_effect` — ограниченная исследовательская экстраполяция HR. Они не являются
абсолютной вероятностью болезни. Значимость ClinVar и носительство не являются диагнозом.

Качество генотипов/FILTER не отсекается автоматически; произвольные indel и
мультиаллельные записи не получают интерпретацию точного SNV. Неоднозначные rsID
для правил возвращаются как `not_evaluated`, а не выбираются по порядку файла.

## Этапы и ответственность

- `service.py` координирует этапы и сохранение снимка.
- `profile_storage.py` отвечает за файловые поколения, метаданные и lock.
- `vcf_parser.py` читает генотипы и считает пропуски.
- `annotations.py` получает полные пакеты MyVariant с повторами и атомарным кэшем.
- `clinvar.py` сопоставляет точные координаты и аллели.
- `genotype_rules.py` применяет декларативные правила из `resources/`.
- `pgs_catalog.py`, `pgs_scoring.py`, `pgs_interpretation.py` разделяют загрузку,
  математический расчёт и сравнение с референсом.
- `clinical_summary.py` отбирает находки; `report.py` преобразует результаты
  в публичные схемы без консольного форматирования.

Сетевые сбои MyVariant не прерывают локальные правила и PGS. Неполный пакет
аннотаций не считается отрицательным результатом. Ошибки программирования
не перехватываются как успешный частичный отчёт.

## Подготовка и эксплуатация

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m src.services.gene_analysis.cache_import
# Только если нет готового референса или изменился каталог моделей:
.\venv\Scripts\python.exe -m src.services.gene_analysis.prepare_reference
```

Импорт копирует только валидные файлы известных моделей, EUR-референс и пакеты
MyVariant. Исправное назначение не перезаписывается; старый CLI сохраняет свои
копии. Подготовка референса использует публичные SNP моделей, не VCF пациента.
Обе команды запускаются отдельно от HTTP-обработки. Кэш MyVariant не имеет TTL;
актуальность классификации требует отдельного обновления источника. При аннотации
во внешний MyVariant передаются rsID с ALT, сам VCF не отправляется.

Каталог `var/` исключён из Git и Docker build context. В текущем Dockerfile код
копируется в `/`, поэтому пример постоянного тома:

```powershell
docker run -p 80:80 -v persomed-gene-data:/var/gene_analysis persomed-server
```

При изменении WORKDIR измените и путь тома. Существующая система не содержит
аутентификации: привязка к `patient_id` обеспечивает изоляцию файлов, но не вводит
проверку прав пользователя. Новый сервис следует текущей архитектуре доступа.

## Проверки

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\venv\Scripts\python.exe -m unittest discover -s tests -v
.\venv\Scripts\python.exe -m pip check
```

Тесты используют синтетические данные, временные каталоги, отдельную SQLite и
подменённые сетевые вызовы. Проверяются сохранение снимка, замена, ошибки, блокировки,
контракт и ссылки, фаза, точность ClinVar, PGS/EUR/HR и численная совместимость с CLI.

Ручная проверка через `/docs`: создать пациента → получить пустой профиль → загрузить
VCF → получить отчёт → повторить GET и сравнить `generated_at` → загрузить файл повторно
→ получить новый `profile.id` и новый отчёт. Дополнительно проверить неверный VCF,
несуществующего пациента, другого пациента и удаление пациента.
