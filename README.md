# PersoMed

PersoMed — прототип медицинской информационной системы с цифровым профилем пациента, показателями здоровья, документами и анализом генетического профиля. Репозиторий состоит из [клиента](client/README.md) на React, TypeScript и MUI и [сервера](server/README.md) на FastAPI с SQLite. Страница генетического профиля обращается к серверному API; для локальной проверки она использует пациента с ID `1`.

## Требования

- Python **3.11.8** (версия сервера указана в [`server/.python-version`](server/.python-version)).
- Node.js **18 или новее** и npm.
- Доступ в интернет для установки зависимостей и первого получения внешних аннотаций генетического анализа.

Команды ниже приведены для **PowerShell** и выполняются из корня репозитория, если не указан другой каталог.

## Подготовка при первом запуске

Создайте виртуальное окружение сервера и установите зависимости:

```powershell
cd .\server
py -3.11 -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe -m alembic upgrade head
```

Если база новая и в ней нет пациента № 1, заполните её демонстрационными данными:

```powershell
.\venv\Scripts\python.exe scripts/fill_database.py
```

Путь к SQLite задан относительно `server/`, поэтому сервер, миграции и скрипт заполнения запускайте **из этого каталога**. Не запускайте заполнение повторно поверх базы с нужными данными.

Установите зависимости клиента в другом терминале:

```powershell
cd .\client
npm ci
```

Если виртуальное окружение, база и `node_modules` уже подготовлены, эти шаги можно пропустить.

## Запуск

Откройте **два терминала PowerShell** в корне репозитория и оставьте оба процесса работающими.

**Терминал 1 — сервер:**

```powershell
cd .\server
.\venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8000 --reload
```

**Терминал 2 — клиент:**

```powershell
cd .\client
npm run dev
```

Откройте [генетический профиль](http://localhost:5173/genes). [Swagger UI](http://localhost:8000/docs) показывает маршруты сервера. На странице `/genes` можно загрузить несжатый VCF v4 с одним образцом, посмотреть отчёт и его источники. Первый анализ большого файла может выполняться долго. Загрузка нового VCF заменяет текущий файл и его сохранённый отчёт.

Клиент по умолчанию обращается к `http://localhost:8000`. Если адрес API отличается, задайте `VITE_API_BASE_URL` в `client/.env.local`. CORS сервера по умолчанию разрешает `http://localhost:5173` и `http://127.0.0.1:5173`; для другого адреса задайте `PERSOMED_CORS_ORIGINS` перед запуском сервера. Параметры описаны в README [клиента](client/README.md) и [сервера](server/README.md).

## Проверка изменений

```powershell
cd .\client
npm run build
npm run lint
```

```powershell
cd .\server
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Структура и ограничения

- [`client/`](client/README.md) — страницы и интерфейс; генетический профиль расположен по маршруту `/genes`.
- [`server/`](server/README.md) — API, база данных, миграции и обработка профиля.
- [Описание генетического анализа](server/src/services/gene_analysis/README.md) — формат VCF, жизненный цикл отчёта, кэши и ограничения интерпретации.

Генетический отчёт предназначен для экспертного разбора. Неполный ответ источника не равен отсутствию варианта, а перцентиль PGS показывает положение относительно EUR-выборки, не вероятность заболевания. Клинически значимые находки требуют подтверждения и сопоставления с данными пациента. Для проверки используйте синтетические данные; не добавляйте реальные данные пациентов в репозиторий.
